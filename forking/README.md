# Forking ODD

**Epistemic Status:** Practice / Policy Candidate  
**Lifecycle:** Current  
**Summary:** ODDの一部または全部を、別のContext・Product・Teamで分岐、変更、再解釈するためのGuide。

## Fork Welcome

> **分岐・改変歓迎です。**

GitHub RepositoryをForkする、一部Conceptだけ使う、別の前提へ置き換える、ODDとは違う結論へ到達する、ODDを批判するためにForkすることも歓迎します。

## You Do Not Need to Adopt ODD

ODDをPackageとして受け入れる必要はありません。Co-Explorerだけ、Observation to Designだけ、Knowledge State Mapだけを使っても構いません。

> **Partial adoption is still a valid exploration.**

## Forking Is Not Failure to Follow ODD

Fork先のRealityで何が残り、何が壊れ、何が変化するかを見ることに価値があります。

> **Forking can be part of Discovery.**

## Preserve Status When You Fork

Open CandidateをForkしたからといってEstablished Principleへ自動昇格するわけではありません。Fork先で別途検証しStatusを変える場合は、そのDifferenceが分かる形を推奨します。

## Your Reality Has Priority in Your Fork

元ODDとFork先Realityが衝突するなら、元ODDへRealityを合わせる必要はありません。

> **Rules do not outrank Reality.**

## Keep the Difference Visible

元ODDから何を変えたかが見えると、何が壊れたか、改善したか、どのContextで有効か比較しやすくなります。

## You May Rename or Reject Things

ODD用語を維持する必要はありません。Conceptを統合、分割、Renameしても構いません。Meaning Authority、AI Role Separation、Reality Firstなどの前提自体をRejectするForkもあり得ます。

## Contribution Back Is Optional

Forkで得たKnowledgeを元ODDへ戻す必要はありません。Private利用でも、別Communityでの発展でも構いません。

> **Contribution back is optional.**

外部Feedbackも自動的にCurrent ODDへ採用されません。

## Forks Can Disagree With Each Other

異なるForkが反対方向へ進んでも構いません。

> **Different Reality can produce different Design.**

## Forking and Meaning Authority

ODD自身についても Accept / Reject / Revise / Reinterpret / Replace できます。

> **ODD itself should remain revisable outside ODD.**

## A Simple Forking Process

```text
1. Pick something useful
2. Identify its current status
3. State what context is different
4. Use / modify / reject it
5. Observe what happens
6. Keep the difference if useful
```

## Questions Worth Bringing Into a Fork

What survives? / What breaks? / What changes? / What was unnecessary? / What appears?
