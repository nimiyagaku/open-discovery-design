# User0 Selected Observations

**Epistemic Status:** Observation  
**Lifecycle:** Current Reference  
**Representation:** Selected / Public Abstracted  
**Summary:** Ideas開発中にUser0について観察されたことのうち、Public ODDで参照可能なものを選択して記録したもの。

## Publication Note

User0はIdeasのProduct Owner本人です。

そのため、このPublic Documentでは、User0本人に関するObservationのうち、Product Owner自身が公開可能と判断できる範囲の情報を掲載しています。

ただし、User0 Observationの中に含まれるThird-party Information、Company / Organization Information、Private Context、Product Competitive Detailなどは、User0本人に関する情報とは別にPublic Boundaryを確認します。

> **User0がProduct Ownerであることは、User0 Observation全体を無条件に公開できることを意味しません。**

このDocumentは、本人に関する公開判断と、第三者・Product・Businessに関する公開境界の両方を通過したObservationだけを扱います。

## What Is User0?

Ideasでは、Product Owner自身がProductを使うとき、意識的に **User0** というRoleへ切り替えることがあります。

```text
Product Owner → Design / Decide / Improve
User0         → Experience / React / Observe
```

目的はProduct Owner自身を完全に客観化することではありません。

> **「設計者としての説明」と「Userとして実際に起きた反応」を少し分離し、メタ認知しやすくする。**

Roleを明示することで、AIからのObservationや批判も「Product Owner本人への評価」より「User0について何が起きたか」として扱いやすくなる場合があります。

## Scope

> **User0 Observation ≠ User一般についてのObservation**

ここからHuman一般、Ideas User一般、AI User一般へ直接一般化しません。必要ならHypothesis / Candidateを作り、別のRealityで確認します。

## Selected Observations

### Interest Can Be Suspended Without Disappearing
User0ではInterestが存在していても探索を続けないことがありました。Cognitive Load、Timing、Fear、Other Prioritiesなどが関係している可能性があります。

「探索を止めた = Interestがなくなった」とは限りません。ただしInterestが必ず残っているとも言いません。

### Brief Can Work as Context Resume
一度中断した探索で短いBriefが、以前どこを見ていたかを思い出すContext Resumeとして機能する場合がありました。

Resumeできることと、Resumeを要求することは別です。

### AI Dialogue Can Change the Question
AIとのDialogue中のReframe、Distinction、Hypothesisなどによって、最初のQuestion自体が変化することがありました。

Questionは探索の入口だけでなく、探索の結果として生まれることもありました。

### Reality Proximity Can Increase Load
抽象的に考えている間は探索できても、実際にやる、他者へ伝える、決める、CommitするといったRealityへ近づくことでCognitive LoadやFearが増える場合がありました。

### Interest Can Shift Naturally
Dialogue中に見つかった別のDifferenceへInterestの中心が移ることがありました。元の探索からの「脱線」とだけ見る必要はない可能性があります。

### Structured and Unstructured Thinking Can Alternate
自由に考える → Structureする → また自由に考える、という往復がありました。Structureを早く固定しすぎると新しいDifferenceが見えにくくなる場合もあります。

### Explanation and Reaction Can Differ
Product Ownerとして合理的に説明できるDesignでも、User0として触ると違和感が出ることがありました。

> **Design RationaleとExperienced Realityの間のTension**

として残します。

### Criticism Can Feel Different When the Role Is Explicit
User0というRoleを明示することで、「あなたの判断が間違っている」より「User0にはこのReactionが見える」としてObservationや批判を受け取りやすい場合がありました。

## User0 Is Not a Substitute for User Research

User0はProduct Intent、Internal Context、Design Reasoningを知る特殊な位置にいます。

> **User0は外部Userの代わりではありません。**

User0 ObservationからUser1以降のBehaviorを予測できるとは限りません。

## User0 Observation and Design


User0で良かったDesignがUser一般に良いDesignとは限りません。
