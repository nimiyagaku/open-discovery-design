# Handoff

**Epistemic Status:** Practice / Candidate  
**Lifecycle:** Current  
**Representation:** Public Abstracted  
**Summary:** Project Continuityを保ちながら、過去のInterpretationをCurrent Realityより強くしないためのContext Allocation Practice。

> **Inheritance is continuity, not imitation.**

## Handoff Is Not a Clone Operation

新しいAIやRoleへ引き継ぐ目的は、前のAIのPersonalityやInterpretationを再現することではありません。

> **Current Repository / Current Observation > inherited interpretation**

HandoffはContextです。Authorityではありません。

## Curated Handoff

必要に応じて次を含めます。

- Current Product State
- Current Reality
- Current Decisions
- Current Candidates
- Open Questions
- Known Risks / Tensions
- Relevant Sources
- Do Not Assume
- Immediate Next Step

重要なのはContentだけでなく **Epistemic Statusを引き継ぐこと**です。

CandidateをDecisionとして、ObservationをGeneral Truthとして渡さないようにします。

## Preserve Uncertainty

HandoffではQuestionやContradictionも残します。綺麗なStoryへ統合しすぎると、新しいRoleが過去FramingへAnchoringされます。

## Handoff Is Context Allocation

すべてのRoleに同じHandoffを渡す必要はありません。Fresh Reviewでは、意図的にHandoffを渡さないこともあります。

```text
Context Loss ←→ Context Overload
```

Continuityの価値とIndependent Perspectiveの価値をRoleごとに調整します。

## Human Cognitive Cost

良いHandoffはProduct Ownerが「Project Memory Courier」になるCostを減らします。しかしHandoff自体を過剰に詳細化するとMaintenance Costが増えます。

> **Knowledge Architectureの完全性より、継続できる運用を優先する。**

## Public Boundary

Public ODDで公開するのはHandoffのMethodです。Actual PO Context、Current Product Detail、Competitive LearningなどはInternalに残る場合があります。

Public Handoff DocumentはInternal HandoffのMirrorではありません。

## Product Owner Authority and Guardrails

Operational RulesはRealityに応じてPOがOverrideできる場合があります。ただしProtective GuardrailsはPO自身を含む重大なHarmから守るため、必ずしもOverride可能ではありません。

> **Authority does not mean unrestricted self-exemption.**

HandoffもRuleではなくPracticeです。Realityと衝突すれば変更します。
